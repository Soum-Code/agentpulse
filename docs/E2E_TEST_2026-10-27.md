## 3. Findings

| ID | Finding | Status |
| :-- | :-- | :-- |
| F1 | The landing page logged `<polygon> attribute points: Expected number, "68%,35 63%,31 63%,39"` on every visit: the drift schematic's arrowhead used percent coordinates, which an SVG polygon does not accept. The arrowhead never drew. | **Fixed** in this PR (`PublicExperience.tsx`: the arrowhead is now a marker on the line). Checked on a local dev server: no console error |
| F2 | At a window 1366 px wide (and any width under about 1780 px) the console header's right-hand controls (project button, **Sign In**, **Public Site**) were pushed out of the window and could not be reached. The header's right block had `shrink-0` and is 1,733 px wide. | **Fixed** in this PR (`ProductHeader.tsx`: the block wraps to a second row). Checked at 1366 px on a local dev server: Sign In and Public Site at x = 1217 and 1341, nothing clipped; the header is 122 px tall there. No unit test: the effect is layout, which the jsdom test setup cannot measure |
| F3 | APM says "ALL SYSTEMS OPERATIONAL" and also "EVALUATOR 1 of 22 alive": 21 of the 22 registered workers are stale ones from earlier deploys (`/v1/health` lists `workers_stale: 21`). It is true, but alarming to read. | Open. Needs a decision on pruning the worker registry; not a few-line change |
| F4 | A repeat hallucination run inside 15 minutes shows high scores and no alert (item 12). | Not a bug; explained on the Lab page. Know it before the demo |
| F5 | The Experiments view is empty on the live instance. | Not a bug; the page says why |
| F6 | These tests added data to the live database: 3 Lab traces, 1 chat trace, 5 alerts (Incidents 15 to 16), all under the service names `simulation_studio` and `rag_chat`. | Left in place (no delete route, and deleting is not part of this task) |
